# أتقن مهارتي — التوزيع الإلكتروني

منصة React/Vite للمعلمة أ. ذكرى آل صديق — متوسطة وثانوية جميما.

## ما توفره النسخة

- تسجّل الطالبة باسمها وبريدها وكلمة مرور، وتؤكد بريدها وتستعيد كلمة المرور بنفسها. يُنشأ ملفها تلقائيًا بعد التأكيد دون تدخل المعلمة.
- تدخل الطالبة ببريدها وترى نتائجها وسجل محاولاتها ومهارات التعزيز فقط. تظل الحسابات السابقة برمز وكلمة مرور مؤقتة مدعومة، ويمكن للمعلمة إنشاء حسابات بالرمز اختياريًا.
- تحفظ الاختبارات والتحديات في Supabase، وتبقى البيانات عند تحديث الواجهة أو النشر على Netlify.
- يصحّح الخادم الاختبارات، ويعتمد أول قبلي وآخر بعدي. لا يقبل درجـة يرسلها المتصفح.
- لوحة المعلمة لإنشاء الحسابات، وإعادة كلمات المرور، ومتابعة النتائج وتصدير CSV ولقطة JSON.
- تقرير قابل للطباعة وحفظ PDF؛ لا يحتوي أسماء أو نسب تجريبية. التحسن محسوب للطالبات اللاتي أكملن القياسين.
- الشرح والمختبر متاحان للتصفح. حفظ الاختبارات وتحدي «خطأ نودّعه» يتطلب حساب طالبة.

## التفعيل لأول مرة

**التسجيل الذاتي بالبريد:** اتبع `EMAIL_SETUP.md` لتفعيل التسجيل العام وConfirm email وURL Configuration وربط SMTP. إعداد الإرسال مرة واحدة لمسؤول المنصة.

1. أنشئ مشروعًا في [Supabase](https://supabase.com/dashboard) خاصًا بالمدرسة. إذا لديك قاعدة بيانات قائمة، لا تحذفها؛ خذ نسخة منها وتحقق من عدم تعارض أسماء الجداول الثلاثة قبل تطبيق الملف.
2. من SQL Editor شغّل `supabase/schema.sql`. ينشئ جداول جديدة دون حذف بيانات. جميع الجداول محمية بـRLS ولا تمنح المتصفح وصولًا مباشرًا.
3. من Authentication > Users > Add user أنشئ حساب المعلمة ببريدها وكلمة مرور قوية، مع تأكيد البريد. لا ترسل كلمة المرور في المحادثة أو تضعها في الكود.
4. في `supabase/bootstrap-teacher.sql` استبدل `REPLACE_WITH_TEACHER_EMAIL` ببريد المعلمة ثم شغّل الملف. ترقية المعلمة لا تتم من واجهة الطالبات.
5. من إعدادات Authentication فعّل Allow new users to sign up وConfirm email للتسجيل الذاتي، واضبط الإرسال كما في `EMAIL_SETUP.md`. اترك تسجيل الدخول بكلمة المرور مفعّلًا، وراجع حدود محاولات الدخول والإرسال المناسبة.
6. شغّل `supabase/verify.sql` وتأكد من تفعيل RLS وعدم منح anon أو authenticated صلاحيات قراءة/كتابة الجداول.
7. اجلب Project URL ومفتاح `anon` ومفتاح `service_role` من إعدادات Supabase. تدعم المنصة أيضًا المفاتيح الجديدة: ضع `sb_publishable_…` بدل anon و`sb_secret_…` بدل service_role مع إبقاء أسماء متغيرات البيئة كما هي. يجب أن تكون القيم الثلاث من نفس المشروع. لا تنشر المفتاح السري ولا تستخدم بادئة `VITE_` معه.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث.

```powershell
npm ci
Copy-Item .env.example .env
```

املأ `.env` محليًا بالقيم الثلاث، ثم:

```powershell
npm run dev
```

افتح `http://127.0.0.1:5173`. يشغّل Vite نفس دالة API محليًا. بدون الإعداد تظهر رسالة انتظار التفعيل ويمكن تصفح الشرح. `npm run preview` معاينة للواجهة المبنية فقط، ولا يشغّل الدوال.

## النشر على Netlify

استخدم مستودع Git خاصًا ثم اربطه بـNetlify، أو استخدم Netlify CLI لنشر المشروع مع الدوال. رفع `dist` وحده بالسحب والإفلات لا يكفي، لأنه لا يتضمن الخادم.

- Build command: `npm run build`
- Publish directory: `dist`
- Functions directory: `netlify/functions`
- Node: `22` (محدد في `netlify.toml`)

أضف المتغيرات التالية في إعدادات Netlify، بنطاق Functions/runtime، ثم أعد النشر:

```text
SUPABASE_URL
SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
```

إذا اختلف رابط الموقع النهائي عن الرابط الموجود في `index.html`، حدّث canonical وog:url وروابط صور المشاركة إلى رابطك النهائي. استخدم HTTPS في الإنتاج. لا تضع بيانات الإنتاج في معاينات عامة غير موثوقة؛ اربط المعاينات بقاعدة اختبار منفصلة.

## التحقق قبل تسليم الرابط للطالبات

1. دخول المعلمة ببريدها ثم إنشاء حسابين تجريبيين خاصين بالتحقق.
2. دخول الطالبة الأولى وتغيير كلمة المرور، وإكمال القبلي والتحدي والبعدي. تحديث الصفحة يؤكد بقاء النتائج.
3. الدخول من جهاز آخر بالحساب نفسه والتأكد من ظهور النتائج.
4. دخول الطالبة الثانية والتأكد من خلو سجلها وعدم وصولها إلى لوحة المعلمة أو التقرير.
5. التأكد من ظهور نتائج الطالبة الأولى في لوحة المعلمة بعد التحديث، وتجربة تصدير CSV وطباعة التقرير.
6. إعادة كلمة مرور الطالبة والتأكد من إلزامها بتغييرها، ثم تسجيل الخروج على الجهاز المشترك.

لا يمكن إثبات اتصال قاعدة البيانات الحقيقية أو نشر الموقع دون تزويد بيئة النشر بهذه القيم. اختبارات المستودع تستخدم خدمة بديلة معزولة ولا تكتب بيانات في Supabase حقيقي.

## البيانات القديمة والنسخ الاحتياطي

النسخة السابقة تحفظ في localStorage، وليست قاعدة مركزية. قبل الانتقال افتح النسخة القديمة من نفس المتصفح والرابط، واحتفظ بالبيانات. في صفحة الدخول الجديدة توجد أداة تنزيل البيانات القديمة إذا كانت موجودة **على نفس الأصل**؛ رابط Netlify الجديد لا يستطيع قراءة بيانات localhost أو نطاق آخر. لا تُحذف البيانات القديمة ولا تُنسب تلقائيًا لطالبة لأن هويتها غير معروفة.

زر JSON في لوحة المعلمة يصدر لقطة لسجلات المنصة فقط، ولا يشمل مستخدمي Auth أو كلمات المرور؛ لا يُعد نسخة كاملة قابلة للاستعادة من المشروع. احتفظ أيضًا بنسخة قاعدة بيانات وAuth باستخدام أدوات النسخ الاحتياطي الرسمية في Supabase، وحدد مسؤولًا للنسخ الدوري. احفظ الملفات المصدرة في مكان خاص.

الحساب الأساسي هو `futureoflife025@gmail.com`، ويجب أن يكون بريد الحساب مؤكدًا وملفه بصلاحية معلمة.

لإضافة معلمة: تنشئ حسابًا ببريدها وتؤكده وتسجّل الدخول مرة واحدة. يدخل المسؤول الأساسي إلى لوحة المعلمة ثم «إدارة المعلمات»، ويضيف بريدها. يمكنه تفعيل «السماح لها بإضافة معلمات أخريات». المعلمة المفوضة تضيف معلمات لمتابعة النتائج؛ تفويض إدارة المعلمات وسحب الصلاحيات يبقيان للمسؤول الأساسي. جميع المعلمات يطلعن على جميع الطالبات والتقارير.
